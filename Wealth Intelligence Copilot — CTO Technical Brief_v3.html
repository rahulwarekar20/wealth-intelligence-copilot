What It Is

WIC is an AI-native investment copilot that turns a brokerage portfolio into a continuously analysed, conversational decision-support system. A user enters their holdings; seven coordinated AI agents retrieve live market data, search a financial-evidence knowledge base via RAG, and compose plain-English portfolio strategy in seconds — replacing static robo-advisor dashboards with a reasoning layer that can explain every conclusion it reaches.

The core proposition: individual investors get portfolio intelligence previously available only to wealth managers with Bloomberg terminals and research teams, without AUM fees.

7-Agent Architecture (LangGraph)

The orchestration layer is built on LangGraph — a directed acyclic graph framework from LangChain that enforces typed state transitions between agents. Every message flows through a DecisionState TypedDict, making each hop observable, testable, and independently restartable without re-running the full pipeline.

LangChain & LangGraph — How They're Used

LangGraph — Orchestration

LangGraph provides the state machine that connects agents. The graph is defined as a Python TypedDict (DecisionState) with fields for query, ticker, history, portfolio data, evidence fragments, market data, and the final recommendation. Edges are conditional: the Supervisor inspects intent and decides which specialist nodes to activate. This replaces brittle if/else routing with a declarative, observable graph that can be visualised, replayed, and extended by adding a new node without touching existing agents.

LangChain — Agent Tooling & Retrieval Chain

LangChain wraps the Groq API calls (using the OpenAI-compatible interface) and provides the retrieval chain that connects the Evidence Retriever agent to pgvector. It handles prompt templating, context-window management, and the structured output parsing that turns LLM responses into typed Python objects consumed by downstream agents.

Conversation memory is implemented as a sliding window buffer: the last 6 turns are serialised into conversation_history: list[dict] and injected into the Supervisor's system prompt, enabling coherent follow-up responses without a separate memory store.

Chunking Strategy

Financial research documents are split into 512-token chunks with a 64-token overlap. The overlap preserves sentence continuity across chunk boundaries — critical for financial text where a number at the end of one sentence is explained in the next. LangChain's RecursiveCharacterTextSplitter respects paragraph and sentence boundaries before falling back to character splits, so chunks do not break mid-table or mid-sentence.

Embedding & Indexing

Each chunk is embedded using an OpenAI-compatible embedding model and stored in PostgreSQL via the pgvector extension. pgvector's HNSW index supports sub-millisecond approximate nearest-neighbour search at the scales relevant to a financial evidence corpus (<100k chunks). Choosing PostgreSQL for both relational data and vectors eliminates an external vector-database dependency and simplifies the deployment topology.

Retrieval Strategy

At query time, the user's question is embedded with the same model. The Evidence Retriever agent performs a cosine similarity search returning the top-5 most relevant chunks. These fragments are injected verbatim into the Composer agent's context window with their source metadata, making every recommendation grounded in retrievable evidence rather than LLM parametric memory. Duplicate evidence inserts are caught with an IntegrityError guard that rolls back and returns the existing record — preventing crashes when multiple agents concurrently write the same evidence.

Investment Readiness Assessment

WIC is a technically credible, working proof of concept. The hard engineering problems — multi-agent orchestration, RAG retrieval, live data parallelisation, conversation memory, typed state graphs — are solved and deployed. The gap to a production-grade investment platform is well-scoped and consists entirely of execution work: brokerage data integration, a continuously refreshed evidence corpus, and regulatory positioning. None of these are research problems. A team of 3–4 engineers could close the gap to a defensible pilot in 3–4 months.

Strengths

  • Modular architecture — each LangGraph node is independently testable and replaceable; adding an agent does not touch existing ones.
  • Auditable reasoning — LangGraph state machine makes the full decision path observable; critical for financial regulation (explainability requirements under SEC guidance).
  • RAG reduces hallucination risk — recommendations cite retrievable evidence rather than relying on parametric LLM memory.
  • Engineering discipline — 40 tests, graceful error recovery, cache invalidation, and parallel fetch performance optimisation distinguish this from a prototype.
  • Model cost efficiency — fast 20b model for specialist reasoning; expensive 120b only at the final synthesis step; both on Groq for low latency.

Risks to Evaluate

  • Manual holding entry is a real UX barrier for mainstream adoption; Plaid integration is the standard fix.
  • Evidence corpus freshness is a core quality variable — stale research degrades recommendation quality; a production ingestion pipeline is required before commercial launch.
  • Regulatory pathway (investment advice) requires legal structuring before monetisation; the most defensible route is white-labelling under an existing RIA.
